# 제품별 발주 계획 대시보드 (Streamlit)

엑셀로 만들었던 "발주계획" 시트를, BOM/재고/생산입고 데이터를 매번 업로드해서 쓰는
**웹 대시보드**로 옮긴 버전입니다.

## 실행 방법

```bash
pip install -r requirements.txt
streamlit run app.py
```

`http://localhost:8501`이 열리면 엑셀 파일을 업로드해서 시작합니다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `app.py` | Streamlit 화면 (업로드 → 제품 선택 → 2단계 입력 → 계산 결과) |
| `calculations.py` | 계산 로직만 모아둔 순수 함수 (생산이력 요약, 필요수량/발주수량/발주권장일 등) |
| `data_prep.py` | 생산입고현황 원본 데이터 정리 함수 (날짜 접미사 제거, 빈 품목코드 행 제거) |
| `requirements.txt` | 의존 패키지 |


## 업로드할 엑셀 파일 형식

| 시트명 | 필요 컬럼 |
|---|---|
| `제품_BOM` | 제품코드, 제품명, 품목코드, 품목명, 수량 |
| `최신재고현황` | 품목코드, 품목구분, 품목명[규격], 재고수량 |
| `생산입고현황` (또는 `생산입고조회`) | 일자, 품목코드, 수량 (그 외 출고창고명/입고창고명/품목구분/품목명/생산금액은 있어도 무방) |

`생산입고현황`은 ERP에서 뽑은 원본을 그대로 올려도 됩니다 — 업로드 즉시 `data_prep.py`가 아래를 자동으로 정리합니다.
- 일자 끝에 붙는 `' -1'`, `' -2'` 같은 순번 접미사 제거 후 `YYYY-MM-DD`로 통일
- 품목코드가 비어있는 행(맨 아래 합계행, 날짜만 있는 행 등) 제거

## 화면 사용 흐름

1. **제품 선택** — 드롭다운(타이핑으로 검색 가능)에서 제품을 고릅니다.
2. **자동 조회 정보 (🔒)** — 제품 현재고, BOM 자재 목록(품목코드/품목명/개당실제투입량/현재고/구분)이 참고용으로 바로 보입니다. 수정 불가.
3. **① 생산계획 & 자재입력** — 생산 목표 수량, 생산마감일자, 생산소요일, 기준일자를 입력하고, 자재별 카드(펼침)에서 예상로스율 / 주문업체 / 국내·외 / 리드타임 / 입고예정수량 / MOQ를 입력합니다. `[다음 단계로 ▶]`를 눌러야 다음 단계로 넘어갑니다.
4. **② 안전재고 설정** — 상단에 방금 입력한 생산계획(생산 목표 수량/생산마감일자/생산소요일)을 참고 정보로 보여준 뒤, 이 제품의 생산입고 이력을 Plotly 라인차트로 보여줍니다 (2025-01-01부터 오늘까지, 생산이 없었던 날은 0으로 채운 연속 시계열이라 스파이크가 잘 보입니다). 생산 횟수/총생산량/평균생산량/최근생산량 요약과 함께, **안전재고 수량을 직접 입력**합니다 (개월 배수가 아니라 실제 수량, 생산계획을 먼저 보고 정할 수 있도록 이 순서로 배치했습니다). `[◀ 이전 단계로]`로 1단계로 돌아가거나, `[📊 발주 계획 계산하기]`를 눌러야만 결과가 계산됩니다 — **1단계에서는 계산 버튼 자체가 보이지 않습니다.**
5. **계산 결과** — 제품 레벨 요약(실제 생산 필요량/최적 생산 시작일/자재 최대 리드타임/현재고/안전재고) + 자재별 필요수량·발주수량·발주권장일 표. 발주 시점이 임박(3일 이내)하거나 지난 자재는 행이 노랑/빨강으로 강조되고, 지난 자재는 목록으로 따로 안내됩니다. 최적 생산 시작일이 이미 지났으면 🚨 경고가 뜹니다.
6. **엑셀 다운로드**로 결과를 내보낼 수 있습니다 (화면 표와 동일한 내용의 .xlsx 파일).

두 단계 모두 각각 `st.form`으로 묶여 있어서, 입력 중간에 값 하나 바뀔 때마다 화면이 재계산되지 않습니다. 생산계획·안전재고 값과 자재 입력값은 제품코드별로 세션에 저장되어, 단계를 앞뒤로 오가거나 다른 제품을 봤다가 돌아와도 유지됩니다. (Streamlit 위젯은 렌더링되지 않는 단계에서는 값이 사라질 수 있어서, 단계를 넘어갈 때마다 값을 위젯과 별개로 세션에 저장해두는 방식으로 구현했습니다.)

## 계산 로직

- **실제 생산 필요량** = MAX(0, (생산 목표 수량 + 안전재고) − 제품 현재고)
  → 안전재고는 이제 사용자가 생산입고 이력을 참고해서 **직접 입력하는 수량**입니다 (예전처럼 "몇 개월치"를 자동 곱해서 산출하지 않습니다).
- **소요량(자재)** = 실제 생산 필요량 × 개당실제투입량(BOM) × (1+예상로스율), 올림
- **필요수량(자재)** = MAX(0, 소요량 − (자재 현재고 + 입고예정수량))
- **발주수량** = 필요수량을 MOQ 배수로 올림 (MOQ=0이면 필요수량 그대로)
- **최적 생산 시작일** = 생산마감일자 − 생산소요일
  → "마감일을 맞추려면 늦어도 언제 생산을 시작해야 하는지"
- **발주권장일** = 최적 생산 시작일 − 리드타임(일)
  → "생산 시작일에 자재가 맞춰 들어오려면 늦어도 언제까지 발주해야 하는지"

## 배포 (Streamlit Community Cloud)

1. GitHub에 이 폴더를 새 저장소로 push (`.streamlit/config.toml` 포함, `requirements.txt`에 `plotly` 포함되어 있는지 확인)
2. [share.streamlit.io](https://share.streamlit.io) → New app → 저장소/브랜치 선택 → Main file path에 `app.py` 지정 → Deploy

로컬 전용으로 썼던 `enableXsrfProtection=false` 같은 설정은 클라우드 배포용 `config.toml`에는 포함하지 않았습니다.

## 지금까지 반영된 주요 수정 이력

- 제품/자재 안전재고 분리 적용 (자재는 현재 미적용)
- "발주예상일" → "발주권장일"로 명칭·계산식 수정 (생산 시작일 − 리드타임)
- 안전재고가 실제 자재 소요량에 반영되지 않던 버그 수정 (`실제 생산 필요량` 도입)
- "생산 시작 예정일" 직접 입력 → **생산마감일자 + 생산소요일**로 역산하는 "최적 생산 시작일"로 변경
- 안전재고를 "개월 배수" 입력 → **수량 직접 입력**으로 변경, 근거 자료로 생산입고 이력 라인차트(Plotly) 제공
- 데이터 소스를 월별재고수불부(출고 기준) → 생산입고현황(생산 기준)으로 교체, `data_prep.py`로 원본 정리 자동화
- 입력값/자동값을 표·카드로 명확히 분리, 자재 입력은 표 대신 펼침 카드 방식으로 변경
- 탭 구조 → **2단계 마법사(wizard)** 구조로 변경: 안전재고 설정을 마치고 다음 단계로 넘어가야만 계산 버튼이 보이도록 개선
- 마법사 단계 순서를 **① 생산계획&자재입력 → ② 안전재고 설정**으로 변경 (생산계획을 먼저 보고 안전재고를 가늠할 수 있도록), 2단계 상단에 1단계 입력값 요약 표시
- 단계를 앞뒤로 오갈 때 위젯 값이 사라지던 버그 수정 (위젯과 별개로 세션에 명시 저장하는 방식으로 변경)
- 제품 선택을 사이드바 → 본문 중앙 박스로 이동
- 결과 표에서 D-day 컬럼 제거(강조 색상 계산에는 계속 사용), 발주 지난 자재는 목록으로 안내
- 발주 필요 없는 자재는 "발주 필요없음" 텍스트로 표시 (None 노출 방지)
- 결과 다운로드를 CSV → **엑셀(.xlsx)** 로 변경

## 다음 단계로 고려해볼 만한 것

- 자재 안전재고를 해외/장리드타임 자재 등 선택적으로 적용
- 입력값을 세션이 아니라 DB/CSV에 저장해서 새로고침해도 유지
- 여러 제품을 한 번에 보는 "전체 발주 필요 목록" 뷰
- 실제 발주 이력(입고예정수량)을 수기 입력이 아니라 발주관리 데이터와 연동
