# 제품별 발주 계획 대시보드 (Streamlit)

엑셀로 만들었던 "발주계획" 시트를, BOM/재고/수불부 데이터를 매번 업로드해서 쓰는
**웹 대시보드**로 옮긴 버전입니다.

## 실행 방법

```bash
pip install -r requirements.txt
streamlit run app.py
```

`http://localhost:8501`이 열리면 엑셀 파일을 업로드해서 시작합니다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `app.py` | Streamlit 화면 (업로드 → 제품 선택 → 입력 → 계산 결과) |
| `calculations.py` | 계산 로직만 모아둔 순수 함수 (Streamlit 없이도 단위 테스트 가능) |
| `requirements.txt` | 의존 패키지 |
| `.streamlit/config.toml` | 서버 설정 (업로드 용량 등) |
| `run_with_chrome.bat` | (Windows) 기본 브라우저와 상관없이 Chrome으로 바로 여는 실행 스크립트 |

## 업로드할 엑셀 파일 형식

| 시트명 | 필요 컬럼 |
|---|---|
| `제품_BOM` | 제품코드, 제품명, 품목코드, 품목명, 수량 |
| `최신재고현황` | 품목코드, 품목구분, 품목명[규격], 재고수량 |
| `월별재고수불부_병합` (또는 `_선별`) | 기준날짜(YYYY-MM), 품목코드, 품목명, 입고, 출고, 재고 |

## 화면 사용 흐름

1. **제품 선택** — 드롭다운(타이핑으로 검색 가능)에서 제품을 고릅니다.
2. **자동 조회 정보 (🔒)** — 제품 현재고, BOM 자재 목록(품목코드/품목명/개당실제투입량/현재고/구분)이 참고용으로 바로 보입니다. 수정 불가.
3. **직접 입력 (✏️)** — 폼(form) 안에서:
   - 생산 목표 수량, 생산 시작 예정일, 재고 기준일, 안전재고 기준(개월)
   - 자재별 카드(펼침)에서 예상로스율 / 주문업체 / 국내·외 / 리드타임 / 입고예정수량 / MOQ
   - **[📊 발주 계획 계산하기]** 버튼을 눌러야만 아래 결과가 갱신됩니다 (입력 중 자동 재계산 안 함).
4. **계산 결과** — 제품 레벨 요약(실제 생산 필요량/현재고/안전재고/3개월평균출고량/자재 최대 리드타임) + 자재별 필요수량·발주수량·발주권장일 표. 발주 시점이 임박(3일 이내)하거나 지난 자재는 행이 노랑/빨강으로 강조되고, 지난 자재는 목록으로 별도 안내됩니다.
5. **CSV 다운로드**로 결과를 내보낼 수 있습니다.

## 계산 로직

- **소요량(자재)** = 실제 생산 필요량 × 개당실제투입량(BOM) × (1+예상로스율), 올림
- **실제 생산 필요량** = MAX(0, (생산 목표 수량 + 안전재고) − 제품 현재고)
  → 안전재고가 이 값을 통해 자재 소요량까지 실제로 반영되도록 계산
- **3개월평균출고량** = 기준일이 속한 달 포함 최근 3개월 평균 출고량 (제품에만 적용)
- **안전재고** = 안전재고기준(개월) × 3개월평균출고량 (제품에만 적용, 자재는 0 — 필요 시 확장 가능)
- **필요수량(자재)** = MAX(0, 소요량 − (자재 현재고 + 입고예정수량))
- **발주수량** = 필요수량을 MOQ 배수로 올림 (MOQ=0이면 필요수량 그대로)
- **발주권장일** = 생산 시작 예정일 − 리드타임(일)
  → "생산 시작일에 맞추려면 늦어도 언제까지 발주해야 하는지"

## 배포 (Streamlit Community Cloud)

1. GitHub에 이 폴더를 새 저장소로 push (`.streamlit/config.toml` 포함)
2. [share.streamlit.io](https://share.streamlit.io) → New app → 저장소/브랜치 선택 → Main file path에 `app.py` 지정 → Deploy

로컬 전용으로 썼던 `enableXsrfProtection=false` 같은 설정은 클라우드 배포용 `config.toml`에는 포함하지 않았습니다.

## 지금까지 반영된 주요 수정 이력

- 제품/자재 안전재고 분리 적용 (자재는 현재 미적용)
- "발주예상일" → "발주권장일"로 명칭·계산식 수정 (생산일 − 리드타임)
- 안전재고가 실제 자재 소요량에 반영되지 않던 버그 수정 (`실제 생산 필요량` 도입)
- 입력값/자동값을 표·카드로 명확히 분리, 자재 입력은 표 대신 펼침 카드 방식으로 변경
- 모든 입력을 폼으로 묶어 버튼을 눌러야만 재계산되도록 변경
- 제품 선택을 사이드바 → 본문 중앙 박스로 이동
- 결과 표에서 D-day 컬럼 제거(강조 색상 계산에는 계속 사용), 발주 지난 자재는 목록으로 안내
- 발주 필요 없는 자재는 "발주 필요없음" 텍스트로 표시 (None 노출 방지)

## 다음 단계로 고려해볼 만한 것

- 자재 안전재고를 해외/장리드타임 자재 등 선택적으로 적용
- 입력값을 세션이 아니라 DB/CSV에 저장해서 새로고침해도 유지
- 여러 제품을 한 번에 보는 "전체 발주 필요 목록" 뷰
- 엑셀(.xlsx) 다운로드 지원 (현재는 CSV만)
- 실제 발주 이력(입고예정수량)을 수기 입력이 아니라 발주관리 데이터와 연동
